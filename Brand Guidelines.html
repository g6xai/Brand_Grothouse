Grothouse Design System v2.0.0

Brand Guidelines

Apple Human Interface Guidelines, for the Grothouse brand and everything it touches. Black, white, grey, and one accent per surface.

Precedence

The canonical standard is DriveX/design/APPLE-HIG-STANDARD.md. It is measured against apple.com rather than asserted, and it carries a decision log recording where its own rules were reversed by re-measurement.

It is deliberately not copied into this repository. A duplicated standard across fifteen repos guarantees divergence, and this organisation has paid for that twice — both times a document describing a rule its enforcement did not have.

Where this page and the canonical standard disagree, the standard wins and this page is the bug. Local deltas are recorded in docs/APPLE-HIG-STANDARD.md.

The colour law

Two accents exist. One per surface, always consumed as --color-primary. A hex literal in a component is a violation, and there is no exception for just this once.

ScopeGroundAccent
Grothouse default, platforms, websites, logos black / white / grey Co-Operate Blue
G26xM, Xperience, Zeus, consumer-facing black / white / grey Xperience Teal

Measured, not asserted

Every ratio below is produced by scripts/contrast.mjs against these exact surfaces and recorded in kit/tokens.json. Re-run it before changing any colour.

The teal has a constraint

#0E8C74 measures 3.84:1 on the light background. That clears the 3:1 bar for UI boundaries, focus rings and text at 22px and above, and fails the 4.5:1 bar for body text.

The hex is fixed by the colour law and ships in production today, so it is kept rather than forked. Accent-coloured text below 22px and filled button labels use --color-primary-text (#0B7A64, 4.84:1) instead.

Apple's own buttons measure a 980px radius — the single most common radius on their home page. Buttons are pills. Inputs and selects stay at 12px, which keeps the control family related to cards while staying rectangular.

Depth comes from materials

The radiance layer — aurora mesh, drifting orbs, noise, grid texture, text glow, divider glow — is retired. Depth now comes from translucency with backdrop blur for floating chrome, and from surface-tone steps for elevation.

Atmospheric gradients behind a compensation ledger contradict deferring to content — the content is the interface. Hierarchy comes from grouping and background, not from outlining every element. A hairline is a last resort, not a default.

Controls

One filled primary per screen. Never two competing filled buttons in the same view. A destructive action is never the filled primary unless destruction is the screen's purpose.

17px is what stops iOS Safari auto-zooming the viewport on focus. That is the zoom users actually complain about.

ConditionMinimum target
Any touch device, any width44 × 44px
Viewport below 768px44 × 44px

Keyed to pointer type, not viewport width — a touch laptop at 1024px is still a touch device. Minimum 8px gap between adjacent targets.

Mobile — the three most-broken rules

1. The document scrolls

html and body stay position: static and overflow: visible. Pinning them stops mobile Safari collapsing its URL bar, permanently costing about 110px of viewport and the native back, share and tabs affordances. A fixed shell makes a product behave like a kiosk. Fixed chrome uses sticky or fixed positioning on the element.

2. Never constrain the document

touch-action and overscroll-behavior are never set on html or body. apple.com leaves both at auto; constraining them at document level is exactly what breaks chrome collapse. overscroll-behavior: contain belongs on inner scroll regions only.

3. The trap

overflow-y: visible computes to auto whenever the other axis is auto, scroll or hidden. So a single overflow-x: auto silently makes a container a vertical scroll container and re-traps the document.

overflow-x: clip is the only value that does not force the other axis. Never reach for overflow-x: hidden as a shortcut.

And clipping is not fixing: flip to clip only in the commit that brings the last overflowing route to zero. Expect overflow counts to rise before they fall — raising body type to 17px surfaces more overfill, it does not create it.

Horizontal carousels are sanctioned

apple.com's iPhone page ships five snap-scrolling carousels on mobile. Horizontal scroll is not the defect — unintentional horizontal scroll is.

Peer set

Comparable cards, never one record split across columns.

Snapped

Snap type mandatory, align start on every child.

Peeking

The peek is the affordance. Without it the content looks complete.

Contained

Inline overscroll containment stops the swipe chaining into browser back.

A data table is never a carousel. Columns of one record are not a peer set. Tabular data becomes a list below 768px and a comparison table above it.

The lint enforces this by reading the declaration block: horizontal overflow is a violation unless the same block carries a snap type. A carve-out the lint cannot see is how 66 violations sat undetected in another repo indefinitely.

States are required, not optional

Loading

Skeleton matching the real layout. Never a bare spinner.

Empty

Title, one explanatory sentence, and the action that creates the first item.

Error

What failed in plain language, plus a retry control. Never a raw error string.
